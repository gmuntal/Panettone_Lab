# Panettone Lab v0.12.0 — sonda de temperatura de massa

La sonda ESP32-C3 es consulta per HTTP autenticat a
`http://10.85.3.103/api/status`. El Shelly continua mesurant temperatura i humitat
ambientals. La temperatura de massa no participa en el control de la manta.

## Estat verificat abans de la integració

- Firmware ESP32 `0.1.0`, xarxa `MG_gurb`, sonda
  `28:19:94:2E:10:00:00:54`, dispositiu `panettone-probe-01`.
- L'usuari ha confirmat lectures estables després de soldar el muntatge.
- Des de la Raspberry `10.85.3.213` s'ha rebut JSON autenticat amb `valid: true`,
  temperatura `21.44`, edat de mostra `523 ms` i `error_count: 0`.
- La reserva DHCP de `10.85.3.103` per a `64:E8:33:AD:41:DC` queda pendent de
  confirmació. S'ha de fer al servidor DHCP que serveix aquesta xarxa.
- Aquestes comprovacions elèctriques no acrediten l'aptitud alimentària del
  conjunt: les proves continuen a l'aire fins a resoldre la beina i la higiene.

## Comportament

Un fil de treball independent consulta la sonda cada 30 segons mentre el
seguiment està actiu i la sonda habilitada. Un timeout de la sonda no bloqueja
el lector del Shelly ni la càmera. Aturar el seguiment també atura aquest registre.

La configuració té la sonda desactivada per defecte. A Configuració es pot
activar/desactivar i canviar la URL privada. La configuració es desa a SQLite;
els valors d'entorn d'activació i URL només s'utilitzen per inicialitzar-la.
El token es llegeix de l'entorn en cada arrencada i no es retorna al navegador.

Només s'accepten el dispositiu i la ROM previstos, schema 1, temperatura i
offset finits, estat vàlid, mostres amb edat màxima de 15 segons incloent-hi el
temps de la petició, i seqüències noves dins la mateixa arrencada. Es rebutgen
85 °C exactes, coherència brut/corregit incorrecta i lectures repetides/regressives.
Un `boot_id` nou permet recuperar-se d'un reinici del dispositiu.

Un error es desa com a registre sense temperatura. La targeta deixa de mostrar
una temperatura actual quan falla l'última consulta, està desactivada, el
seguiment està aturat o la lectura desada té més de 70 segons amb l'interval
per defecte. Aquest marge s'ajusta a `2 × interval + 10` per a intervals més llargs.
No es recuperen retrospectivament les lectures perdudes durant una caiguda de xarxa.

## Històric, gràfics i API

La migració és additiva: crea `dough_probe_settings` i `dough_probe_readings`.
No reescriu ni elimina lectures ambientals, fotografies ni fermentacions.
Les noves lectures de massa s'associen a la fermentació activa quan es desa la
resposta; fora d'una fermentació queden sense associació.

La targeta «Temperatura massa» és independent de l'ambiental. El gràfic de
condicions comparteix l'escala de temperatura per a ambient (verd) i massa
(blau); la humitat manté la seva escala independent. L'eix horitzontal utilitza
les marques de temps reals. Les mostres errònies i els salts de més de 90
segons trenquen les línies. El gràfic pot mostrar l'històric de la sonda encara
que actualment estigui desactivada.

- `GET /api/probe`: configuració pública, estat, edat i temperatura actual.
- `POST /api/probe`: sessió web autenticada; `{ "enabled": true, "url": "http://10.85.3.103/api/status" }`.
- `GET /api/probe/readings?hours=24&fermentation_id=1`: historial amb sessió web.
- `GET /api/v1/probe/readings`: historial paginat amb el token de només lectura
  de Panettone Lab; filtres `start`, `end`, `limit`, `offset`, `fermentation_id`.
- `GET /api/v1/status`: afegeix `dough_probe`, sense canviar els camps existents.

El token de l'ESP32 és diferent del `READONLY_API_TOKEN` de Panettone Lab. Cap
d'aquests tokens autoritza canvis de configuració a través de l'API de només lectura.
Els ZIP inclouen `dough_temperature.csv`, amb les lectures de massa i la seva
qualitat, mantenint `readings.csv` amb el format ambiental anterior.

## Desplegament

1. Fer una còpia del volum `panettone_lab_data` abans d'actualitzar.
2. Publicar aquesta versió pel procés GitHub Actions/GHCR existent i comprovar
   que la imatge nova s'ha publicat abans de redeployar la Stack. El codi local
   per si sol no actualitza el contenidor existent. Amb un tag fix, publicar-lo
   i seleccionar-lo explícitament; amb `latest`, verificar el build abans de
   fer «re-pull image».
3. Incorporar a la Stack les quatre variables de `docker-compose.yml`:

   | Variable | Valor |
   |---|---|
   | `DOUGH_PROBE_URL` | `http://10.85.3.103/api/status` |
   | `DOUGH_PROBE_TOKEN` | Token de lectura mostrat per l'ESP32; guardar-lo privat |
   | `DOUGH_PROBE_ENABLED` | `false` per deixar l'activació a la interfície |
   | `DOUGH_PROBE_INTERVAL_SECONDS` | `30` |

4. Redeployar sense esborrar ni recrear el volum persistent.
5. A Configuració, activar la sonda i desar. Iniciar el seguiment si està aturat.
   En uns 30 segons ha d'aparèixer la primera lectura.

Si la base de dades ja havia inicialitzat aquesta configuració, canviar
`DOUGH_PROBE_ENABLED` o `DOUGH_PROBE_URL` a Portainer no sobreescriu els ajustos
desats a la web. El token sí que s'actualitza en reiniciar el contenidor.

La URL admet HTTP, port 80 i IPv4 privada, sense redireccions ni credencials
incrustades. HTTP no xifra el token: mantenir-ho en una LAN de confiança.

## Validació

Resultat local: 77 proves Python superades i 1 omesa perquè requereix fotografies
reals opcionals; 27 proves JavaScript superades. També s'ha revisat la interfície
en navegador a mida d'escriptori i a 390 × 844, amb dades fictícies i sense
connexions a dispositius reals des del servidor de prova. S'ha comprovat que
desactivar la sonda retira la temperatura actual i conserva la lectura ambiental.

Proves locals automatitzades de conservació de dades, lectura correcta,
calibratge sense doble correcció, autenticació, errors de xarxa, reconnexió,
frescor, seqüències, pausa/configuració durant una petició, associació a sessions,
exportació i gràfic. No s'ha substituït el firmware estable de la sonda.

Després del desplegament encara cal verificar des del contenidor real:

- Primera lectura i aparició al gràfic i al ZIP de la fermentació.
- Desconnectar l'USB de la sonda: targeta sense temperatura actual al cicle següent,
  amb ambient i càmera operatius; reconnectar i comprovar la recuperació.
- Activar/desactivar la sonda i reiniciar el contenidor comprovant persistència.
- Comparació amb un termòmetre de referència i prova prolongada.

La revisió de publicació ha repetit les proves locals (77 Python superades,
1 opcional omesa i 27 JavaScript superades) i ha recuperat l’accés SSH a la
Raspberry. Abans del desplegament s’ha verificat v0.11.2, seguiment actiu,
controlador aturat, sortides Shelly apagades i control real desarmat. La
configuració del token i les comprovacions físiques es completen al servidor;
cap credencial forma part d’aquesta publicació.
